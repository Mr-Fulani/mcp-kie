# Подключение KIE к своему SaaS

Статус на 2026-10-04. Это план интеграции, а не заявление о готовом production backend.
ТЗ v1.1, §§1, 34–39 предусматривает изображения, видео и аудио уже для локального
MCP; SaaS — отдельный поздний этап. Friendly-команды полезны и одному пользователю.

## Что можно переиспользовать

- `KieClient`: ограниченные API-операции, редактирование секретов в ответах,
  защищённые HTTPS-соединения, отсутствие автоматического повтора платного POST.
- `KieService`: discovery/schema, live-сравнение моделей и параметров с ценой,
  immutable prepare/execute, получение состояния и скачивание результата.
  Без `model` friendly-команда возвращает выбор; SaaS-клиент должен показать варианты
  и передать выбранную модель. Явный `auto_select=true` выбирает только по известной
  цене среди первых 20 кандидатов, без независимой оценки качества/скорости.
- `Ledger`: локальные общие лимиты, резервирование, защита от дублирования,
  сохранение обязательств после неопределённого результата отправки.
- Проверки загрузок, MIME, путей, DNS/SSRF и допустимых хостов результатов.

Локальный MCP работает через stdio. Не публиковать его в интернете. FastAPI должен
вызывать общий сервисный слой из доверенного worker, со своим ключом и политикой.
Локальный media key, личный ledger и настройки агентов не переносить в SaaS.

## Что нужно доработать до запуска

| Область | Сейчас | Доработка и критерий готовности |
|---|---|---|
| Backend API | Нет FastAPI приложения | Авторизованные endpoints создания/статуса задач; проверка доступа к каждой задаче и файлу, rate limiting |
| Пользователи | Один локальный владелец | Tenant/user identity, изоляция данных, квоты и бюджет каждого пользователя; тест доступа между пользователями |
| Очередь | Вызов в MCP процессе | Durable job queue/Celery и workers; восстановление после перезапуска; ограничение параллелизма |
| Лимит обращений KIE | Metadata throttle внутри процесса, retries; concurrent preview получил 429 | Общий rate limiter между workers/процессами, Retry-After и backpressure; не повторять ambiguous paid POST |
| Финансы | Один SQLite ledger и owner policy | Отдельные SaaS лимиты, атомарное резервирование в общей БД для всех workers, billing/refunds и журнал; тест конкурентных запросов |
| Идемпотентность | Локальные digest/session approvals | API idempotency keys и persistent сопоставление user/job/provider task; повтор после сетевого сбоя не создаёт вторую оплату |
| Webhook | Только вспомогательный HMAC helper | Проверить актуальный контракт подписи KIE; receiver с проверкой подлинности, replay protection и дедупликацией; polling fallback |
| Подпись webhook | Helper подписывает task ID и timestamp | Не считать helper доказательством совместимости с KIE или подписью всего body; проверить состояние у провайдера перед финализацией |
| Callback | Локальный payload допускает только model/input | Отдельный проверенный backend contract для callback; не открывать произвольный callback URL через локальные tools |
| Результаты | Новые локальные папки дата/label/тип/модель/task ID, временные KIE URL | Скачивание в S3/R2/MinIO, постоянный object key, авторизованная выдача/signed URLs, retention и lifecycle policy |
| Загрузки | Локальный upload root | Изолированные uploads/object storage, лимиты размера, проверка контента и прав пользователя; исключить произвольный fetch |
| Секреты и изоляция | macOS Keychain/Docker Secret | Secret manager/deployment secret, отдельный media key, ограничение egress и прав worker; подтверждённые caps на стороне KIE |
| Модели и цены | Live-каталог/схемы/цены на каждый вызов; пагинация сравнения; reviewed тарифы выбранных личных моделей | Проверенные модели и схемы SaaS сценариев; расширить проверенные тарифы на нужные duration/resolution/quality условия без угадывания цены |
| Неопределённая отправка | Liability удерживается | Процедура reconciliation по истории провайдера, операторский интерфейс и аудит; не повторять платную отправку автоматически |
| Наблюдаемость | Локальные отчёты | Метрики очереди/стоимости/ошибок, алерты, структурированные логи без ключей и приватного контента |
| Эксплуатация | Локальный runtime | Backup/restore БД, миграции, staging, rollback, нагрузочные и security проверки затронутых границ |

`Ledger` не имеет модели пользователей, а `KieService.session` принадлежит процессу.
Переиспользование одного экземпляра в многопользовательском backend само по себе
не обеспечивает изоляцию или правильное распределение затрат.

## Рекомендуемый порядок интеграции

1. Определить нужные сценарии и протестировать конкретные модели/параметры/цены.
2. Сделать backend identity, persistent jobs, tenant budgets и idempotency.
3. Подключить очередь и worker с отдельной политикой/секретом.
4. Добавить проверенный webhook с polling fallback и reconciliation.
5. Перенести результаты в собственное хранилище и проверить права доступа.
6. Проверить сбои, конкурентные запросы, restore и rollback в staging.

## Что не блокирует личную работу

FastAPI, очередь, multi-tenant billing, object storage и production webhook не нужны
для ручной работы одного владельца через stdio. Независимая оценка качества/скорости
моделей — улучшение router, а не условие ручного выбора модели.

Для личного использования нужны рабочие friendly-команды, понятные previews,
проверенные нужные media-сценарии, сохранение лимитов и ясная обработка ошибок.
На 2026-10-04 friendly previews выбранных image/video моделей проверены; их тарифы
распознаются через reviewed профили (PRICE_SUPPORT.md). Первый paid video завершился
ошибкой Lite; затем все шесть friendly paid workflows и оба Mini video-режима прошли
в последовательном проходе. Проверены выбранные личные модели, не SaaS deployment.
При SaaS интеграции учитывать expiry промотарифов, фактические размеры/MIME и
раздельную атрибуцию account balance/provider task usage.
Фактический статус и оставшиеся проверки: [PERSONAL_USE.md](PERSONAL_USE.md).
