# Шпаргалка Secure KIE MCP

Для повседневной работы запускайте свой CLI и пишите обычным языком. Регистрация
`kie-media` уже подключена у владельца в Codex, Claude Code и Grok Build. После
обновления перезапустите сессию CLI. Новая установка: [GETTING_STARTED.md](GETTING_STARTED.md).
В примерах ниже сначала используются сравнение/preview; платная генерация — только
в пределах вашего поручения после просмотра модели, параметров и цены.

## Готовые запросы агенту

| Задача | Что написать |
|---|---|
| Выбор модели фото | «Через Secure KIE MCP сравни модели для фото товара. Покажи цену, форматы и разрешения, дождись моего выбора» |
| Новая картинка | «Создай изображение [описание] через KIE MCP. Сначала предложи модели и покажи preview выбранной» |
| Студийное фото | «Сделай студийное фото товара из uploads/images.jpg: белый фон, мягкий свет. Сохрани форму, цвет и детали товара. Сначала модели и цена» |
| Удалить текст/водяной знак | «Через edit_image убери наложенный текст и водяные знаки, восстанови фон. Надписи/логотипы на самом товаре оставь. Сначала покажи модель и цену» |
| Убрать фон | «Удали фон images.jpg через remove_background, сохрани прозрачность и края объекта. Сначала цена» |
| Увеличить фото | «Предложи модели upscale_image для увеличения images.jpg в 2 раза. Покажи допустимый масштаб и цену» |
| Видео по тексту | «Сравни модели для видео [сцена], 4 секунды, 480p, без звука. Дождись выбора модели» |
| Оживить фото | «Сделай видео из images.jpg: [движение], 4 секунды, 480p, без звука. Сначала сравни модели и цену» |
| Сохранить результат | «Скачай готовую задачу [task_id] через kie_download_result, название студийное фото. Покажи папку результата» |
| Проверить баланс | «Вызови kie_get_credits через Secure KIE MCP, без генерации» |

Файл должен находиться в разрешённом uploads. Относительное имя интерпретируется
от uploads, а не от checkout. Точная image preview может загрузить файл в KIE;
сравнение моделей фото не загружает. Не передавайте свои ключи агенту.

## Какая команда за что отвечает

| Команда | Назначение |
|---|---|
| `kie_compare_models` | Живые кандидаты, параметры, цены; query и cursor/next_cursor для поиска/страниц |
| `generate_image` | Новое изображение по описанию |
| `edit_image` | Редактирование фото, включая удаление наложенного текста/водяных знаков |
| `product_image_create` | Фото товара: стиль, фон, пропорции |
| `remove_background` | Удаление фона |
| `upscale_image` | Увеличение/улучшение изображения |
| `generate_video` | Видео по тексту или фото |
| `kie_get_task` / `kie_wait_for_task` | Статус и ожидание уже отправленной задачи |
| `kie_download_result` | Сохранение успешного результата в настроенную папку |

Без `model` friendly-команда показывает варианты. С выбранным `model` и
`dry_run=true` возвращает exact preview без платной отправки/резерва. Незнакомая
цена — unknown, не бесплатно. Дополнительные поля модели передаются в `model_input`;
например, звук — `generate_audio=false`, если это допускает выбранная схема.
Ни разрешение, ни длительность, ни формат не гарантируются для всех моделей.
Качество/скорость не ранжируются независимо от провайдера.

После одобрения: `kie_prepare_task` → `kie_execute_task` с тем же model/input и
approval_id в той же MCP-сессии → wait → download. Не повторяйте платную отправку
после таймаута: сначала сверка состояния/истории KIE. После рестарта старое approval
не исполняется новой сессией; уже отправленную задачу можно проверять по task_id.

## Диагностика и обновление

Из корня checkout:

```sh
uv sync --frozen --extra dev
.venv/bin/kie-mcp-doctor
.venv/bin/kie-mcp-doctor --check-secret
codex mcp get kie-media
claude mcp get kie-media
grok mcp doctor
```

Doctor без сети/изменения файлов; по умолчанию ключ не читает. `--check-secret`
проверяет загрузку без вывода значения, а не валидность ключа на стороне KIE.
CLI authentication/chat-provider errors — отдельны от подключения media MCP.
В обычной эксплуатации dev extra необязателен; он нужен разработчику для тестов.

## Когда несколько агентов расходуют один баланс KIE

MCP записывает собственную отправку по task_id: клиент, сессия, модель, оценка цены
и возвращённые KIE `creditsConsumed`/`costUsd`. Поэтому расходы известных задач
можно отделять от задач других агентов, даже когда баланс аккаунта общий.

Есть предел точности: если KIE не возвращает фактические кредиты/USD, MCP сохраняет
оценку и обязательство. Разница общего баланса также включает чужие задачи/другие
списания и не является доказательством стоимости нашей генерации. Точный итог
требует terminal task usage и при необходимости billing history провайдера.

В текущем ledger нет идентификатора API-ключа и отдельного MCP-инструмента сводного
отчёта расходов. Атрибуция есть по task/client/session, а не по имени ключа. Клиентские
имена — диагностические метки, не надёжная multi-tenant identity. Общий локальный
лимит действует на процессы, использующие одну БД и одинаковую политику. Агенты на
других компьютерах/с другой БД не входят в этот локальный лимит: provider caps нужны
отдельно. Нельзя удалять ledger или считать unknown списания равными нулю.

Ключевые ограничения: точный монтаж/GIF/WebP конвертер не реализованы; результат
генеративного редактирования проверяйте визуально. Для недоверенного shell-агента
нужна отдельная OS/container изоляция. Полная граница: [SECURITY.md](SECURITY.md).
